# FlawScope：简历与面试讲解

适用岗位：应届生或初级 AI 应用开发、LLM 应用工程。以下表述以本仓库的代码和评估报告为准；面试时只讲自己实际完成、能够现场解释的部分。

## 简历写法

**FlawScope｜工业设备故障诊断系统**　Python、FastAPI、LangGraph、Chroma、React

- 设计信息抽取、混合检索、诊断、审核、复议、成本计算与工单生成的状态机；信息不足时追问，资料不足或模型失败时给出带风险说明的工单。
- 实现 BM25 与向量检索的 RRF 融合，结合设备、报警代码与相关性校验限制无依据结论；将备件价格和人工费用交给规则计算。
- 构建单 Agent 对照评估，分别报告根因覆盖、幻觉、排除条件遵守、诚实降级和误降级；保留弃权样本的严格口径，避免降级使准确率分母变小。
- 实现 SSE 进度、并发保护、链路追踪、历史记录与工单导出，并用离线测试覆盖检索、护栏和异常路径。

最终简历只能挑选最相关的三条，按实际负责范围修改动词。性能数字应写明用例数、评估日期及统计口径，不能把旧版本结果当作当前版本成绩。

## 90 秒讲法

“这个项目解决工业设备故障描述不规范、资料不完整时容易误诊的问题。用户输入设备、报警码、现象和已排除条件，系统先抽取结构化字段，再用 BM25 和向量检索找到证据。诊断结果要经过独立审核；审核不通过时根据驳回理由重新取证，复议最多三轮。没有可靠依据、模型异常或复议仍无共识时，系统把原因和风险写进工单，提示人工确认。成本由规则计算。为了验证多 Agent 是否真的有价值，我做了共用检索证据的单 Agent 对照，并同时报告误降级与弃权口径；结果并非所有指标都更好，这也指出了下一步该修哪里。”

## 面试深挖

**为什么用多 Agent？** 审核节点拿到原始报修、检索证据和诊断结论，可以驳回结论并改变状态机路径。复议使用驳回理由重新检索。它的价值应由纠错增益、误改率、额外耗时和成本共同判断，不能仅凭角色数量证明。

**为什么有规则护栏？** 设备和报警码匹配、排除条件、成本计算是可以程序化检查的约束。模型负责理解现象和提出候选原因，规则负责阻止明显越界。护栏也会误伤：E-101 条目的正文块没有“数控机床”，曾触发错误降级；检索结果现在携带入库时保存的设备来源，既保留块级证据，也让护栏能识别所属设备。

**怎样解释实验？** 单 Agent 和多 Agent 使用同一批用例、相同的初始检索证据及同一套判定函数。复议后的重新检索仅供多 Agent 使用，不能提前交给单 Agent。全覆盖率同时报“弃权剔出分母”和“弃权留在分母”两种口径；误降级率、调用失败数和重复运行摆动必须一起展示。不要把一轮小样本或跳过判官的报告称为完整准确率。

**目前最大的限制？** 知识库是维修经验整理，尚缺真实现场工单的外部验证；用例数和知识库外样本数较少。项目适合展示系统设计、可靠性和评估思路，实际现场使用前还需设备专家复核、更多真实案例及持续监控。
