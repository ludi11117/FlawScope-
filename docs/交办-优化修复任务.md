## 批次 A：必须修（真 bug + 免鉴权烧配额）

### A1. 前端多轮上下文自我嵌套，第 3~4 轮必炸

**现状**：`web/src/pages/DiagnosePage.tsx:77-79` 把 `buildContext()` 拼好的整段上下文当本轮输入传给
`start()`；`web/src/hooks/useDiagnosisStream.ts:81` 又把这段**已拼好的上下文**存进 `turns`；
`useDiagnosisStream.ts:186-193` 下一轮给每个 turn 再套一层 `第N轮：`。
结果：第 2 轮 payload 形如 `第2轮：第1轮：A…`，第 3 轮约为前一版两倍（近指数），
最终撞上 `api.py:151` 的 `fault_description max_length=4000` → 422。

**要改**：`turns` 只存用户原文；上下文在 `start()` 内部临时组装、不写回 state；
`buildContext()` 加轮数上限（建议 ≤5 轮）与总长度上限（建议 ≤3000 字符，留出余量）。

**验收**：加前端单测——连续 4 轮后，`buildContext()` 的输出长度随轮次**线性**增长（不是倍增），
且 `第1轮：` 在整串里只出现一次。删掉修复后该断言必须失败。

### A2. FastAPI 422 的 detail 是数组 → 整页白屏

**现状**：`web/src/api/client.ts:56-66` 与 `client.ts:198-208` 把 `body.detail` 直接赋给字符串；
422 的 `detail` 是列表 → `state.error` 变成数组 → `web/src/pages/DiagnosePage.tsx:407` 直接
`{state.error}` 渲染对象 → React 抛错；`web/src/main.tsx:9-13` **没有 ErrorBoundary**，白屏。
历史/统计页走 `request()`，会显示 `[object Object]`。

**要改**：
1. 抽 `extractDetail(body): string`，兼容 `string` 与 `Array<{loc,msg}>`（拼接 `loc.join('.')+msg`）；
2. `textarea` 加 `maxLength={4000}` 与实时字数提示；
3. `main.tsx` 加 ErrorBoundary，兜底页要能显示「界面出错」+ 刷新按钮，而不是白屏。

**验收**：前端单测覆盖 `extractDetail` 的三种输入（string / 数组 / 缺失）；
再用一个假的 422 响应渲染 `DiagnosePage` 的逻辑路径（纯函数层面即可，本仓库不装 jsdom）。

### A3. `/health?fresh=true` 没有鉴权（文档却承诺有）

**现状**：`api.py:479-480` 的 `health` 没有 `Depends(require_api_key)`（全仓只有 8 个业务端点挂了它），
而 `/health` 会真调 **1 次 LLM + 2 次 Embedding**。`docs/PROJECT_GUIDE.md:500` 写着
「`?fresh=true` … 配了 `API_KEY` 时需带 `X-API-Key`」——承诺的保护在代码里不存在。
任何人都能拿它烧配额。

**要改**：`fresh=true` 时强制校验 API Key（`settings.API_KEY` 未配置时保持放行，与现有可选鉴权口径一致）。
`/health/live`、`/health/ready` 保持无鉴权、可高频轮询。

**验收**：新增 `tests/` 用例：`API_KEY` 已配置时，`fresh=true` 无 key → 401、带 key → 200；
`fresh=false` 命中缓存时不触发鉴权（或按你实现的语义写清并断言）。

### A4. 切页/卸载不中断 SSE：结果丢失 + 后端继续烧完剩余节点

**现状**：`web/src/hooks/useDiagnosisStream.ts` 全文没有 import `useEffect`（无任何清理），
而 `web/src/App.tsx:197` 用 `<main key={route}>` 强制重挂载。
诊断中途切 tab → 组件卸载、状态清零、旧 fetch 无人 abort，后端继续跑完 6~9 次 LLM 调用。
（对照 `web/src/hooks/useHealth.ts:147-152` 是有清理的。）

**要改**：hook 内加卸载清理 `useEffect(() => () => { abortRef.current?.(); abortRef.current = null }, [])`；
把诊断状态提升到 `App`/context，去掉 `key={route}` 造成的强制重挂载（或至少保证中断先发生）。

**验收**：一个能观察 `abort` 被调用的单测（把 `diagnoseStream` 换成可注入的假实现即可）。

### A5. 流被静默截断时 `running` 永远为 true（界面僵死）

**现状**：`web/src/api/client.ts:224-244` 读到 `done` 就 `break`，正常结束**不回调任何东西**；
`client.ts:151-156` 定义了 `onDone` 但 `useDiagnosisStream.ts:155-168` 没传；
且不校验 `Content-Type`——代理返回 HTML 200 时也被当流处理。

**要改**：校验 `content-type` 含 `text/event-stream`；循环结束若从未收到 `result` 就兜底
`onError('连接中断，未收到诊断结果')`；补 `onDone`（并让 reducer 有一个明确的 done 收敛）；
给普通请求加超时（建议 15s），给 SSE 加「静默无 chunk 超时」。

**验收**：`sse`/`client` 层单测：① 返回 `text/html` 时立即报错；② 流提前关闭且无 result 时报错；
③ 收到 result 后不再报错。

### A6. 容器内带图诊断会被 nginx 直接 413

**现状**：`web/nginx.conf` 既无 `client_max_body_size` 也无 `gzip`；后端允许的
`image_base64` 上限是 8,000,000 字符（`config.py:127-131`，约 6MB 原图），
而 nginx 默认只放行 1MB → 容器部署下带图请求会被代理挡掉。

**要改**：`client_max_body_size 12m;`、`gzip on;`（压缩 text/css/js/json，别压 SSE）；
`web/vite.config.ts:33` 的 `sourcemap: true` 改成 `false`（nginx 公开 `/assets/`，等于公开源码）；
`web/Dockerfile:15-16` 的 `npm install` 改 `npm ci` 且去掉 `package-lock.json*` 通配。

**验收**：`docker compose config` 能解析；如不能起容器，至少给出改后配置的静态检查结果。

### B4. 检索结果与查询嵌入无缓存

**现状**：`agents.py:611-647` 每次 `retrieve_evidence` 都调一次 embedding API；一次诊断里它最多被调
4 次：初检、每轮辩论（`orchestrator.py:355`）、降级时的 `find_cross_device_hints`（`agents.py:1462`），
而辩论重检索的 query 常与初检高度重叠。

**要改**：给 `retrieve_evidence` 加有界缓存（LRU 或 `_exclusion_cache` 同款做法），

**验收**：单测——同一 query 调两次，断言 `similarity_search` 只被调用 1 次；
`rebuild_bm25_index()` 后再调，断言被调用第 2 次。**必须做退化验证**（去掉缓存该断言失败）。

### B5. 排除条件映射每次都花一次 LLM，而确定性匹配已覆盖大部分

**现状**：`agents.py:1096-1160` 先让 LLM 映射、再与 `_deterministic_exclusion_hits` 取并集；

**验收**：① 构造一个「所有排除项都能确定性命中」的样例，断言 LLM 调用次数为 0；

### B6. `check_relevance` 是额外的完整往返（改动较大，做之前先确认）

## 批次 C：护栏正确性与接口契约

### C1. 确定性设备护栏偏松（已实测）

**实测**（离线探针，真实知识库，8 类设备 × 所有**跨设备**章节 = 259 组）：

```
无报警代码：跨设备证据被放行 20/259 = 7.7%
带报警代码：跨设备证据被放行  3/259 = 1.2%
```

**病因**：`agents.py:715-721` 用 `any(t in evidence for t in tokens)` 做**单 token OR**，
而 `_equipment_tokens`（`agents.py:675-692`）还会把长词降级成 `t[:2]`
（「数控机床主轴电机」→「数控」「机床」），「机床」几乎在任何设备资料里都能命中。
报警代码那条 `len>=3` 的归一化子串检查才是真正在拦的。

**要改**：设备名要求**规范化全名或同义词命中**（而不是任一 2 字前缀），或改成「≥2 个不同 token 类命中才放行」。
注意保持 `README` 里承诺的对偶性：既测「同义不同名要放行」，也测「真不匹配要拦下」——
不要为了压低误放行率把本该放行的同义案例一起拦掉。

**验收**：把上面那段探针固化成**离线测试**（不联网、只用 `data/knowledge_base.txt` 与纯函数），
断言误放行率低于你实现后能达到的阈值（例如 ≤3%），并保留同义放行的对偶用例。
**必须做退化验证**：回到旧实现时该断言失败。

### C2. 检索层没有 metadata、也没有分数阈值

**现状**：`build_knowledge_base.py:127-139` 是 `db.add_texts(chunks)`，**没有 metadatas**。
于是 `agents.py:616` 的 `similarity_search` 无法按设备过滤，也无法把命中块溯源到
「哪个设备 / 哪条原因」（README 把「条目级切分」列为待办，而元数据缺失是它的前置条件）。

**要改**（可分两步，先在报告里说明你选了哪步）：
1. 入库时写 metadata：`{"section": 章节名, "alarm": 报警代码或"", "device": 设备名}`（从章节标题解析）；
2. `retrieve_evidence` 增加可选的设备/报警码过滤（**默认关闭**或做 A/B，
   因为一刀切过滤可能让召回为空 → 误降级；建议作为降级前的二次尝试）。

**验收**：`build_knowledge_base.py --dry-run` 不写库；加一条单测断言切分后的 metadata 能被正确解析；
检索过滤的单测用假 Chroma（沿用 `tests/test_retrieval_explain.py` 的 `_FakeDB` 手法）。

### C3. `run_diagnosis_stream` 每步 yield 的是同一个可变 dict

**现状**：`orchestrator.py:753-768` 一路 `merged.update(...)` 后 `yield (label, merged)`。
SSE 端因为立刻序列化没事，但任何「把每步快照收进列表」的消费方拿到的 N 份快照会**全变成终态**。

**要改**：`yield (label, dict(merged))`（浅拷贝即可），或明确注释契约。建议直接拷贝——代价可忽略。

**验收**：单测——收集所有 yield 的状态，断言倒数第二个的 `status` 不等于最后一个的 `status`。

### C4. `/diagnose` 丢掉 `record_id`，且落库失败会把已完成的诊断变成 500

**现状**：`api.py:219-224` 忽略 `save_diagnosis_record` 的返回值（SSE 版 `api.py:306-327` 是带
`record_id` 的）；这一路没有任何 try/except —— SQLite 一抖，用户等了几十秒的结果直接 500 丢掉。

## 3. 执行流程（每批都照这个来）

1. **先读**：把要改的文件的**函数体**读出来（不要只看 grep 结果），确认任务书描述与代码一致；
   不一致就在报告里写明，以代码为准。
2. **再改**：小步改，串行编辑同一文件；每改完一处立刻 `grep` 复核落盘。
3. **加断言**：每条修复配一个「未修复就会失败」的测试。
4. **退化验证**：临时还原旧行为 → 确认测试变红 → 恢复修复 → 确认变绿。记录失败的断言名。
5. **全量回归**：`pytest -q`（应为 403 + 你新增的数量）与 `ruff check .`（0 问题）。
   前端改动：`npm run typecheck && npm test && npm run build`。
6. **写报告**（见下），然后**立刻进入下一批**；只有 §5.2 列出的 4 项需要先停下来提问。
